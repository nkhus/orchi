# Bootstrap and curate project knowledge

Inspect repository instructions and real implementation before writing current-state claims. Search existing authoritative docs, inspect ownership/related links, and run `lint`. Missing structure is not permission to redesign the system or invent intended behavior as current truth.

## No Core or implementation

Greenfield needs a Git baseline commit and operator policy, not fake product documentation. Current can remain empty. Preserve the original request, author accepted requirements and system-level target architecture under Intent, then plan the first epic against Target. Introduce verified Current knowledge only after its checked, reviewed checkpoint. Policy baseline checks may be empty when appropriate; final verification remains required.

## Existing unstructured docs

Survey actual docs, code and repository conventions. Identify authoritative pages, duplicates, stale claims and missing area entry points. Search before adding pages. Add known kinds to load-bearing nodes, safe artifact ownership and meaningful typed relations; repair real broken links. Keep incidental Markdown outside unnecessary schema ceremony. Missing kinds/indexes and orphans provide deterministic adoption diagnostics.

A normal documentation-only change before an initiative may establish factual Core structure through the project's ordinary reviewed commit process. Once an initiative has begun, do not mutate this initiative's accepted Core: stage verified replacements/indexes in Working Knowledge at an epic checkpoint and reconcile them at final publication. Keep future plans in Intent throughout.

## Structured Core

Reuse the existing authoritative nodes and area indexes. Read exact matching sources with their role/hash, inspect related nodes only when useful, and update the smallest coherent knowledge set. Preserve stable requirement IDs and section anchors when reorganizing target docs. Rebuild disposable search/map outputs after accepted changes.

Parallel curator agents may survey disjoint documentation areas when the host supports it. Give each a bounded scope and real sources; combine findings centrally, resolve ownership/link conflicts and follow the same controller gates. Do not let area curators write Core concurrently with an active initiative or assign themselves authority through metadata.

Mechanical lint cannot establish that prose describes implementation correctly. Reconcile claims against code, tests and evidence, and ask the human to resolve material uncertainty rather than filling unknown facts.
