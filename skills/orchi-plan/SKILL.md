# Plan only the next accepted result

Read next, [planning](../orchi/references/planning.md) and [authoring](../orchi/references/authoring.md).
Use `uv run <skills>/orchi/scripts/orchi.py --control "$ORCHI_CONTROL" ...`.
Inspect Current, actual code/instructions and Target. Greenfield may have no Current.

## Initial direction

Preserve original request bytes and stable requirement IDs. Author necessary target boundaries.
A no-architecture-change statement is valid for a bounded fix; do not invent new components.
Use `start --file brief.json` for a complete compact request/design; its exact initial gate binds both.
Use Intent Markdown, intent-build and begin for larger outcome-level roadmaps.
Do not predesign future file edits or task DAGs. Stop at human acceptance.

## Selected epic

Read accepted integration_base, actual head, verified knowledge_head and Target identity.
Search explicit views, inspect diagnostics and read exact sources before choosing implementation.
Persist the selected Epic Design with requirement/architecture links and exact hash.
Fix shared interfaces; derive a task DAG from the nearest jointly verifiable result.
State fixed decisions/invariants, allowed local choices, initial edits, sources and checks.
Optional scope envelopes permit only named local choices, not semantic changes by folder permission.
Use on-demand exact sources where appropriate; ownership is not a read lock.
Resolve material open questions; use explicit investigation tasks for bounded research.
Knowledge-only epics need no fake coding tasks. Prototype work must not silently become product code.
Run plan-preflight, inspect known/deferred constraints, then submit plan and stop at approval.

## Adapt

Local technical additions use scope-acquire within the accepted envelope.
Use amend-tasks only for impacted pending tasks with identical shared design/acceptance/unaffected contracts.
Shared implementation changes require full amend after workers stop.
Target changes require accepted revise-intent between epics, preserving source/completed history.
For an active epic needing Target change, stop/release and accept stop-epic before revising.
Canonical movement uses explicit code-and-knowledge sync, not rebasing fields or history.
