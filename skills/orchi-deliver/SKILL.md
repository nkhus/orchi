# Reconcile checked reality

Read next and [delivery](../orchi/references/delivery.md), [knowledge](../orchi/references/knowledge.md).
Use `uv run <skills>/orchi/scripts/orchi.py --control "$ORCHI_CONTROL" ...`.

## Epic checkpoint

Require all tasks integrated, exact joint checks and independent review.
Inspect actual changed paths and known documentation impact.
Replace/retire/revalidate sparse Working Knowledge, never future Target as implemented facts.
Dispose every product change and known mapping; submit checkpoint and return to next-epic planning.
Do not edit Core, merge or archive the initiative at an intermediate checkpoint.

## Upstream synchronization

At a closed boundary use [synchronization](../orchi/references/synchronization.md).
Inspect upstream, reconcile exact code conflicts and every affected Core/Working decision.
Run sync-check, route exact sync review, then present human gate and stop.
No new Current before accepted sync. Preserve original source/history and invalidate stale final approval.
Resolve required Target revision before later design/finalization.

## Final result

After every epic closes, inspect coverage and final-draft.
Dispose every requirement, architecture node and Working entry using actual candidate evidence.
Unchanged architecture and non-software not-applicable are explicit checked dispositions, not omissions.
Author Core from reality; preserve valid ontology/links and intentional deviations.
Finalize exact code/docs/archive, route final review, then human acceptance.
Publication gives a policy-bound exact-tree/base local/PR handoff, not a created remote PR.
The operator publishes using allowed Git/hosting rules and records the actual visible commit.
Retain export sidecars for final attestation and internal replay.
No partial-request publication, automatic rebase, forced merge, deployment or distributed atomicity claims.
